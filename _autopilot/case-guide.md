# 네이버 블로그 → 홈페이지 블로그 재작성 기준서

목표: 네이버 블로그(sinabro7500) '이음케어라이프' 카테고리의 글을 **복사가 아닌 새 글**로 다시 써서
ecl.ai.kr/guide 에 올린다. 완성 기준 예시는 이미 발행된 아래 두 편이다. 작업 전 반드시 두 JSON을 읽고 같은 수준으로 맞춘다.

- `_guide/posts/ilsan-bogeum-funeral-3day-case.json`
- `_guide/posts/paju-hanbit-christian-family-funeral-case.json`

## 1. 원문 다루기
- 원문 문장을 그대로 옮기지 않는다. 사실(장례식장, 지역, 장례 형태·종교, 일수, 화장장/장지, 진행 순서)만 가져와 구성과 문장을 완전히 새로 쓴다. (네이버 유사문서 판정 방지)
- **개인정보는 전부 뺀다**: 고인·유족 이름(가린 이름 포함), 나이, 병명·투병 내용, 정확한 날짜(월·일), 호실 번호, 해시태그 속 이름. 날짜는 "1일차 오후 3시"처럼 상대적으로만 쓴다.
- 원문에 사실과 다를 수 있는 정보(세금·지원금·법 기한·가격)가 있으면 WebSearch로 공식 출처(국세청, 정부24, 보건복지부, e하늘 등)를 확인해 고친다. 확인 안 되면 쓰지 않는다. 정보 글에는 `sources` 2개 이상.
- 같은 장례식장 글이 여러 편이면(예: 일산복음병원 3편) 서로 다른 각도로 쓴다: 종교·장례 형태·계절·일정(새벽 임종, 4일장)·유가족 상황 중 그 글만의 특징을 제목과 첫 섹션에 내세우고, 기존 글과 같은 문단·같은 제목 패턴을 쓰지 않는다. 기존 글 목록은 `ls _guide/posts` 로 확인.

## 2. 글 구성 (사례 글 `category: "장례 진행 사례"`)
1. `caseInfo` 개요 카드: 장례식장 / 지역 / 장례 형태(종교·일수) / 장례 방법 / 화장장·장지 / 상조 방식
2. `summary` 3줄
3. 섹션 6~7개 권장 흐름
   - 어떤 장례였나 (상황과 유가족이 원한 방향 — 감정은 담담하고 따뜻하게)
   - 날짜별 흐름 (h3로 1일차/2일차/3일차…)
   - 이 장례만의 포인트 (늦은 밤 임종, 4일장, 종교 예식, 배우자상, 가족장 등)
   - 그 장례식장·지역에서 알아두면 좋은 점 (화장장 동선, 예약, 관내·관외 이용료 확인 권유 등 — 확인된 사실만)
   - 실용 체크리스트 1개 (예: 첫 2시간, 부고 문구, 종교별 준비물, 4일장 비용 차이 표)
   - 후불제 상조라서 가능했던 것 (정산 방식, 필요 없는 구성 빼기 — 과장 금지)
4. FAQ 4~5개 (그 장례식장·형태로 실제 검색할 질문)
5. CTA 2~3개: `[[CTA:call]]`(급한 임종), `[[CTA:consult]]`, `[[CTA:quote]]` 를 독자가 멈출 자리에
6. 관련 글 링크 1~2개 본문에 `<a href='/guide/슬러그'>제목</a>`
- 본문 3,000~4,500자. 제목은 "장례식장명 + 형태 + 후기/사례 + 핵심 포인트" (45자 이내). slug는 영문 `장례식장-형태-case`.

정보 글(원문이 사례가 아닌 경우)은 category를 내용에 맞게(`장례 절차`, `장례 비용`, `사망 후 행정`, `임종 준비` 등) 정하고 사례 카드 대신 핵심 요약·표·체크리스트를 쓴다.

## 3. 사진
1. `python3 _autopilot/photo_tool.py sheet /tmp/naver/<logNo>` → sheet.jpg 를 Read로 **직접 보고** 고른다.
2. 쓰지 않는 사진: 고인의 시신·염습 장면, 영정/위패/유골함/안내판 등 **이름·얼굴이 읽히는 것**(흐림 처리로도 애매하면 제외), 흐림 처리 안 된 유족 얼굴, 원문 제목 글씨가 큰 썸네일 카드.
3. 쓰는 사진: 제단·꽃 장식, 관 위 꽃, 뒷모습 인사, 운구(얼굴 없는 구도), 장의차, 장례식장 복도·시설, 봉안당 전경(이름 안 보이게).
4. 여러 장이 붙은 콜라주는 칸을 하나씩 잘라 쓴다(좌표는 sheet 비율로 추정 후 결과를 다시 Read로 확인).
5. `python3 _autopilot/photo_tool.py crop <원본> images/guide/<slug>/<이름>.webp x0 y0 x1 y1 <가로> [blur x0,y0,x1,y1]`
   - 큰 사진 가로 1000~1200, 갤러리 칸 600. 영정 얼굴이 보이면 blur로 가린다.
   - 자른 결과를 반드시 다시 Read로 확인: 글씨 띠 남음, 얼굴 노출, 이상한 잘림이 있으면 다시 자른다.
6. 섹션의 `gallery: [{src, alt, caption}]` 로 넣는다. 한 글에 사진 3~6장. 캡션에 가림 처리 여부를 밝힌다("영정은 흐림 처리").

## 4. 애니메이션 그림 (글마다 2장, 직접 그림)
- `images/guide/<slug>/cover.svg` (1200×630): 그 장례의 분위기를 담은 플랫 일러스트 + 큰 한글 제목(장례식장명) + 부제(형태·"실제 진행 사례"). 종교별 상징(기독교: 십자가·백합 / 불교: 연꽃·염주 / 일반: 국화·촛불), 시간대(새벽·밤)를 반영. 사람 얼굴은 그리지 않는다.
- 설명 그림 1장: 그 글의 핵심을 시각화(일정 타임라인, 3일장 vs 4일장 비교, 동선 지도, 비용 구조, 체크리스트). 섹션 `figure`로.
- CSS @keyframes만 사용, 스크립트·외부 링크·외부 폰트 금지, `prefers-reduced-motion` 포함, font-family `'Noto Sans KR','Apple SD Gothic Neo','Malgun Gothic',sans-serif`.
- Playwright로 PNG 스크린샷(애니메이션 3~4초 후)을 찍어 Read로 보고 **글자 겹침·잘림·가려진 요소**를 고친다.

## 5. 발행
```
node _autopilot/run.mjs --publish /tmp/post.json --case
python3 _autopilot/naver_fetch.py done <logNo> <slug>
```
- 품질 기준 미달이면 지적된 부분을 보강해 다시 실행.
- 발행 후 `guide/<slug>.html` 을 Playwright(모바일 390px, 스크롤하며 lazy 이미지 로드)로 열어 전체를 확인한다.
